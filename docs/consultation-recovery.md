# 相談呼出しと使用量の回復

相談の物理呼出しの `callId` と予算の `pendingCall.id` は同じIDを使う。使用量の保存後、予算更新前に中断した場合は、同じ呼出ID・相談・プロジェクト・受付送信元の完全な記録を予算へ一度反映する。途中・欠測の記録は解消扱いにしない。回復後も既存の回数・使用量上限を守る。

相談の再開時は使用量保留の判定より先に保存記録を照合する。保存先の読取失敗は呼出しを増やさず返す。存在しない使用量を0で補わない。返信による保留解除の履歴にも呼出IDを保持し、あとで完全な記録を照合できた分を一度だけ計上する。既存の保留解除回数を減らさず、未知の別呼出しがあっても既知の記録の照合を続ける。過去の呼出IDと予算IDが別だった記録は推定で結び付けない。

入力超過による分割AIは、親相談の予算・使用量・呼出IDに記録する。分割のための会話は新規に開始し、通常の相談セッションや添付資料を引き継がない。親に子の本文とIDを保存できた後で中断した場合、元の本文とIDを使って不足している子を作成し、既存の子を保持する。分割AIは呼び直さない。子の作成エラーで停止した場合は、親相談の再試行から同じ処理を続けられる。

相談では実際の標準出力・標準エラーが240秒ない場合にプロセス群を終了する。CPUやファイル入出力だけではこの期限を延長しない。既存の全体期限とプロセス活動の無活動期限も維持し、終了理由とプロセス群の診断を残す。一般のAI呼出しには出力期限を追加しない。

固定検証は実行中の段階を15秒ごとに標準出力へ出す。全体の外側で強制終了されても、最後に観測した段階をコントローラーが取得できる。段階の観測は合格証拠とは別に扱う。
