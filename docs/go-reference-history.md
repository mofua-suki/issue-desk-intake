# 相談の参照と閉じた依頼の経緯

受付AIへ渡す参照は、共通番号と、選択済みプロジェクトの `owner/repo#Gitea番号` を対応表で照合する。他プロジェクトのrepo形式や対応表に無いrepo形式を、同じ数字の共通番号として代用しない。対応が足りなければ通常更新と強制更新を各1回まで試し、一時的な取得失敗は後で再開できるよう例外として残す。

参照の結果は、その参照を書いたuser発言の `references` に保存する。解決済みの発言は再起動・再試行で取り直さない。閉じた依頼では、対象ブランチへPRがマージされたと確認できる場合を除き、閉じた理由・最後の失敗・信頼する監視アカウントの独立レビュー指摘を添える。資格情報を伏せ字にしてから、1参照1500文字・1メッセージ6000文字に収める。壊れた状態コメントや取得できない経緯を、記録なしで埋めない。

経緯を読めなかった参照には `historyUnread=true` を付ける。最後のuser発言に初めて現れた未読の経緯は、AIがreadyを返してもコントローラーが起票を止め、利用者へ経緯を尋ねる。前のuser発言でも同じ番号の経緯を尋ねた後なら、次の返答で再び同じ停止を繰り返さない。この質問は代理AIによる判断で消さない。

開いている依頼の参照資料には、共有DBのジョブと現在の担当表・上限設定から追加指示の受付可否を付ける。実装回数・レビュー保留の上限や記録の読取失敗を、追加指示を受け付ける依頼として扱わない。
