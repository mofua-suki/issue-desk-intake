# 優先度変更Skillの実環境確認

この手順は、配布済みの [priority-issue Skill](../skills/priority-issue/SKILL.md) に従い、NASとUbuntu Workerの出荷窓口で読取と優先度変更を確認する。接続と配布の運用条件は [チャットとLinux PCへの配布](chat-operations.md) を参照する。実行と結果の秘匿処理は運用担当が行う。

## 実施前の条件

- 各環境の配布済みSkill、窓口、稼働ServerとWorkerの版を照合し、日時と識別可能な版を記録する。NASは desk-pc、Ubuntuは desk の既存PCトークン窓口を使う。操作には運用代行許可が必要。
- 検証専用対象、隔離受付などの隔離条件、利用者の指示またはSkillの割り込み条件、既存の操作許可を確認する。各操作の直前に受付の `actions` と状態を再確認し、実行待ちなどの可否判定を維持する。確認できない場合は送らず、実施不能として記録する。隔離先に切り替えられると仮定しない。
- 資格情報の値、認証ヘッダー、設定ファイルの実内容を表示・保存しない。出力や記録は秘匿処理する。認証失敗時に別方式へ自動切替せず、拒否を避けるため権限や状態を変えない。
- high、normal、autoは別操作であり、それぞれ初回送信前に異なる小文字16進UUIDを生成する。highだけ前後の空白を除いて1〜500 Unicodeコードポイントの理由を付ける。他には理由を付けない。各操作の接続先、送り手の識別情報、ID、対象と本文を資格情報を除いて保持する。

## 手順と判定

各環境・各値について、実際に実施した窓口、工程、終了コードを記録する。コマンドの終了直後に終了コードを取得し、出力を秘匿して結果表へ転記する。Skillの例の対象は実際に許可された検証専用対象に置き換える。

各環境で、[priority-issue Skillの手順](../skills/priority-issue/SKILL.md)に従って事前読取、送信、応答確認、事後読取を行う。送信結果が不明な場合の照合も同手順に従う。各工程の終了コード、照合結果、拒否理由を下の表に記録する。

環境を準備できない場合は、環境・項目、具体的な理由、代わりに確かめた方法と結果、残る未確認を記録する。代替確認を実環境の成功実績と扱わない。

不具合には再現条件、期待値、実際の結果、修正の根拠またはコントローラーが登録した別の修正依頼番号を残す。製品の修正は別依頼で扱う。レビューでは各行の欠測、認証・操作権限・受付・現在値の区別、NASの0と現在値確認の区別、秘匿、版と隔離条件を照合する。
