# 相談からマージまでの改善と確認

## 対象と運用条件

受付の資料準備、相談の出力、会話の再利用、AI制限待ちと、受付からWorker APIを経由する回復を対象とする。実装・独立レビュー・固定検証・承認の条件は維持する。最近の稼働件数が少ない場合、合成試験の結果を本番での短縮率や成功率として扱わない。

- リポジトリ内検索は最大4件のファイル取得を並行し、結果とエラーはパス順に扱う。結果上限に達した場合や取消では残る取得を取り消して回収する。既存のblobキャッシュも利用する。
- ファイル一覧はリポジトリと固定コミット単位で共有する。完全に取得した一覧だけを保存し、概算16MiBと128版の上限で古いものから追い出す。失敗・不完全一覧は保存しない。許可されたリポジトリとパスの判定は省略しない。
- 資料要求の途中回答は短い形式を選択できる。追加の分類用AI呼出しを挟まず、起票用の最終回答では従来の完全な形式・根拠・承認・受入条件の検査を行う。
- 相談の会話保持は60分。再利用キーから除外するのは、相談内容に影響しないことを確認した担当表の `assignments.pollSeconds` だけとし、それ以外の設定、モデル、権限、指示を変えると会話の再利用は失効する。
- AI制限の待ちは同じServiceの同じproviderで共有する。この境界は実行器の認証アカウントに対応する。通信障害・認証エラーを制限待ちに変換せず、別Serviceや別providerを停止しない。相談別の保存済み待機・使用量上限・再試行回数とAI枠の解放を維持する。

## 比較の条件

同一のリポジトリ・固定コミット・資料・モデル・難易度・受入条件で旧版と新版を比較し、版と環境、試行数、欠測を記録する。検索を行う相談、追加読取のない相談、返信待ちからの再開を分ける。検索ではキャッシュが空の場合と温まった場合を分け、取得数・同時数・資料準備時間と相談全体の時間を見る。ネットワーク負荷も合わせ、AI時間が支配的な相談へ検索の短縮率をそのまま当てはめない。

既存の依頼別使用量レポートと稼働実績の `waits`・`throughput`・`rework` を使い、相談開始からマージまでの時間、停止・再実装・再レビュー、工程別と合計の使用量を比較する。マージ済み依頼だけの分布と、期間内に始めて未完了・停止した依頼の件数・使用量を別々に確認し、成功例だけで効果を判定しない。難易度・変更規模・リポジトリ・配置版の混在を揃える。欠測はゼロにしない。

会話入力の構造化ログ `event=consultation_session_input` には `mode`、`reset_reason`、`input_bytes`、`full_input_bytes`、`reinput_bytes` を記録する。失効後の全量入力と通常の差分入力を区別し、失効理由ごとの件数と再入力量を集計する。本文・資格情報・会話IDはこの計測へ出さない。bytesは送信文字列の大きさであり、トークン・実請求額・定額枠の消費量へ換算しない。推計額も実請求額と区別する。

制限待ちの比較では、同じproviderへの模擬制限を使って追加呼出数と解消後の完了時間を確認し、別providerと取消を同時に試す。既存の上限・未計測使用量・認証エラーの停止が変わらないことも確認する。

## 回復と回帰検証

受付とWorkerの公開API契約を通す少数の障害試験で、応答消失、実行器の再作成、lease失効と古いepoch、受付へのマージ結果報告の再送を扱う。Issue・PR・マージの記録が重複せず、古い担当の書込みが拒否され、引継ぎ後の処理が許可された完了状態へ進むことを確かめる。Worker内部をimportせず、実DBとAPIの状態遷移を検証する。Worker内部のGiteaマージ応答照合はこの合成試験の対象外とする。外部Gitea・AIの応答を差し替える試験は、実機障害時の全体成功率を保証するものではない。

並列検索・一覧キャッシュには順序、上限、取消、異なる版・リポジトリの分離、不完全取得と再取得の挙動試験を置く。短い途中回答と完全回答の選択、最終検査、会話の失効条件と入力観測、共有待機の範囲を個別試験で守る。全体の固定検証はREADMEの手順を担当PCで実行する。

## 反映と判定

検証と独立レビューを通してマージした後、NASの既存systemd更新で稼働revisionを照合する。マージと稼働反映を分けて記録する。待機・キャッシュはServiceの生存期間に限定され、永続データの形式変更やWorkerの配置変更は必要ない。

回復試験を先に確認し、取得の並列化とキャッシュ、途中回答と会話再利用の順に効果を見る。正常な相談の完了率・最終検査・異なる実行先への影響に悪化があれば、使用量だけの削減を成功としない。実測が揃うまで、削減率や所要時間を約束しない。
