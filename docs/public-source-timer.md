# 定時の公開候補準備と送信

23:00 Asia/Tokyo に候補を準備した後、送信を設定している場合は承認済み対象を一巡する。[一巡送信の手順](public-source-schedule.md#承認済み対象の一巡)に従い、対象ごとに手動確認値または運用担当が審査した自動判定方針を用意する。初回候補を方針に登録する場合は、候補の差分全体を審査する。対象は所有者限定のジョブ登録で追加する。

準備設定は `~/.config/issue-desk/public-source-preparation.env` に `JOBS_REGISTRY`、`PREPARATION_ROOT`、必要に応じて `PREVIOUS_DIR` の絶対パスを指定する。送信する場合は所有者だけが読める `~/.config/issue-desk/public-source-sending.env` に次の絶対パスを指定する。

```ini
SEND_PREPARED_DIR=/private/approved-run
SEND_CONFIRMATIONS_DIR=/private/confirmations
SEND_ISSUER_REGISTRY=/private/app-registry.json
```

定時準備の最新成功結果を使う場合は `SEND_PREPARED_DIR` の代わりに `SEND_PREPARATION_ROOT` に準備側と同じ `PREPARATION_ROOT` の絶対パスを指定する。両方は指定できない。ルートはリンクを含まない所有者専用の実ディレクトリ（0700）にする。準備開始時に前回の記録を無効にし、全対象の準備成功後に相対名を記録する。送信時は準備と排他し、記録が24時間を超える場合や参照が安全でない場合は失敗する。失敗時は原因を確認し、準備から再実行する。送信には審査と、適用される個別承認が必要。

定時準備で固定ルールの機密検査を使う場合、準備環境ファイルの `PUBLIC_SOURCE_SCAN_CONFIG` に所有者専用の通常ファイル（他ユーザーへの権限なし、ハードリンクなし）の絶対パスを指定する。省略すると検査しない。実行前にGitleaks 8.30.1の固定イメージ `ghcr.io/gitleaks/gitleaks@sha256:c00b6bd0aeb3071cbcb79009cb16a60dd9e0a7c60e2be9ab65d25e6bc8abbb7f` を配置担当が用意する。検査はネットワークなしで実行する。

設定は次の形式で、例外がない場合は `exceptions` を空配列にする。例外は対象ID、候補内の正規相対パス、規則ID、検出行の実バイトのSHA-256をすべて照合する。行範囲の間の改行は含め、最後の行終端のLFは含めない（CRLFのCRは含む）。値を設定に書かず、例外ごとに公開済みのテスト値・生成値であることを運用担当が審査する。

```json
{"exceptions":[{"target":"intake","path":"example.txt","rule":"github-pat","sha256":"0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"}]}
```

未知の検出、設定・検査報告の不正、検査の失敗または準備証拠と候補の不一致があれば最新記録を作らない。検出値は出力しないため、運用担当が安全な環境で候補を確認し、原因を解消して準備から再実行する。`no-diff` は候補を検査し、候補のない `skipped` は検査を見送る。どちらも送信されない。

待ち対象を同じ候補で再確認するには、送信環境ファイルに `SEND_WAIT_SECONDS` を1〜3600の整数秒で指定する。全対象の初回処理後、待ち対象だけを約1秒ごとに再確認し、上限で待ち状態を残す。候補、登録、確認値や方針、プレビューが変化した対象は失敗として停止する。省略すると一巡のみ。

送信設定がなければ準備だけを行う。一部だけの設定や不正なパスは失敗する。登録、候補、確認値、発行登録の所有権とアクセス制限は一巡送信の手順に従う。資格情報の値を環境ファイルに書かない。

送信結果は対象ごとの `published`、`merged`、`waiting`、`failed` で確認する。待ちや結果不明の場合は公開先を確認し、同じ候補で再実行する。手動確認する対象は同じ確認値を使う。準備に失敗した場合は送信しない。

定期準備の前に入力参照を更新する場合は、準備環境ファイルに `MIRROR_REFRESH_REGISTRY` として所有者のみが読める実ファイルの絶対パスを指定する。省略時は取得しない。登録は対象IDをキーとし、準備登録の `source.repo` と `ref` に一致するベアミラーとブランチ参照、ミラーに設定済みの上流名を指定する。ミラーは実行ユーザー所有で他ユーザーがアクセスできない実ディレクトリとし、登録と上流設定は運用担当が審査する。

```json
{
  "intake": {"repo": "/private/intake.git", "remote": "origin", "ref": "refs/heads/main", "public": {"repo": "/private/public.git", "remote": "origin", "ref": "refs/heads/main"}}
}
```

任意の `public` は準備登録の `publicRepo` と `publicRef` に一致させ、同じ所有者限定のベアミラーと登録済みremoteを指定する。公開側の上流は資格情報を使わないHTTPSまたはローカルの絶対パスに限る。公開ミラーのローカルGit設定にHTTP設定、資格情報ヘルパー、URL書換え、設定のinclude、remoteのproxy・uploadpack・vcsを指定しない。省略した対象は公開側を更新しない。

指定された参照だけを非対話で取得し、全件がコミットを指すことを確認してから準備する。いずれかが失敗すれば準備と送信を停止し、原因を直して次回再実行する。非公開側のSSHは既存の読み取り専用鍵やエージェントを利用できる。非公開側のHTTP資格情報ヘルパーと追加ヘッダーは既定で無効であり、必要な対象だけ `"httpAuth": true` を指定して既存のGit設定を利用する。資格情報を登録に記載せず、上流URLに埋め込まない。手動準備と送信では更新しない。
