# ホスト作業用SSHの許可を追加する

## 固定操作・対象PCの登録を追加する

利用者が対象PCと目的を示し、既存の枠組みで固定操作を登録できる場合は直接PRで進める。起票・相談は行わない。PRの作成、独立レビュー、検証、マージは [merge-manual-pr](../merge-manual-pr/SKILL.md) に従う。

1. `host-ssh.json` の `hosts`、`operations`、`operationHosts`、`readOnlyOperations` を確認する。登録済みの組み合わせで目的を満たせる場合は、下の手順で実行する。
2. 固定コマンドと実行できるPCの組み合わせを絞る。操作の接続先制限は `operationHosts` に記録する。`operationHosts` に制限がない既存操作は新規PCにも及ぶため、PCを追加するときは自動承認も含む実効範囲を前後で比較し、利用者が許可した組み合わせ以外は既存PCに限定する。実際に読み取り専用で、自動承認することも利用者が許可した操作だけを `readOnlyOperations` に登録する。検証のようにコードを実行する操作は発券前に個別の許可を照合する。新規PCが既存のCAと登録予定のprincipalを受け入れる設定になっているか確かめる。認証・署名役・発券条件や接続先のsshd設定の変更が必要なら、固定登録の直接PR方針でその範囲まで承認済みと扱わない。
3. 既存の方針テストと操作固有の固定検証を担当PCで行う。変更後の `host-ssh.json` に依存する実接続は、マージ後にNAS上の接続入口と受付の方針が更新されてから確認する。新規登録の接続確認に必要な許可は、マージ後に登録済みの対象へ付与する。
4. `host-ssh.json` は権限保護対象。変更するPC・操作・内容とPRのheadを照合し、[直接PRの個別承認](../merge-manual-pr/SKILL.md#個別承認と失敗) を経てマージする。受付で対象版と登録内容・実行結果を確認し、マージと反映を区別して報告する。

## 登録済み操作を実行する

運用代行を許したPCトークンまたは一時キーで、登録済みの読み取り専用操作を申請するときは既存の自動承認を使う。
個別の許可が必要な操作は、[許可の付与](../issue-desk-issue-control/refs/grants.md) に従い、利用者の許可の原文と発言日時を添えて `host-ssh` の `<PC名>:<固定操作名>` に必要最小のTTLで登録する。用後は取り消しと反映を確認する。検証の送り先と実行は [nas-verify](../nas-verify/SKILL.md#重い検証は別pcで流す) に従う。
