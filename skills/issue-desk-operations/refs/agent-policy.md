# 相談元と工程ごとの実行先

相談元の実行先と実装先を混同しない。Codexのチャットから起票するときは `--consultation-provider codex`、Claudeからは `--consultation-provider claude` を必ず付ける。利用者が相談先を明示した場合はその指定を優先する。実装先は別の `--provider` で、利用者の指定がなければCodex。相談・起票前確認・クローズ・優先度判定は記録された相談先を使用し、競合解消・テスト修正は実装先、レビューは実装と反対側を使用する。無効な実行先は使わない。工程別設定・モデルの一時切り替えで規則を上書きしない。

調査だけ・報告だけの依頼はIssueにせず、同じチャットで原記録と資料を確認して回答する。具体的な修正を依頼するときだけ起票する。自動監視から新しい相談・調査・修正・後続Issueを起票せず、実装への言い換えで迂回しない。

受付の版3レビュー後続案だけは、信頼されたWorkerの元コメントとPRのマージを受付が再検証した後、自動起票する例外とする。チャットや一般の自動監視にはこの例外を適用しない。条件は [レビューの後続案](../../../docs/followup-proposals.md) を参照する。
